01

Lesson design

From a learning question to an experiment.

Outcome → prerequisite order → interaction → understanding check.
Read the skill instructions
---
name: course-lesson-design
description: Design or revise an interactive course lesson when learning goals, prerequisite order, explanatory text, experiments, and assessment need to work together.
---
# Design an interactive lesson

Start from the requested learning outcome and the existing lesson. Preserve the instructor's scope, audience, language, and accepted terminology. Ask only for missing information that changes the lesson.

## Decisions to make
- Write an observable outcome: what should a learner calculate, interpret, or distinguish?
- Identify the minimum prerequisite chain. Introduce notation before using it. Do not introduce a later model simply to explain today's statistic.
- Use a motivating situation when it makes the learning question concrete. Keep the scenario separate from evidence.
- Give each interaction a learning purpose: predict, change one variable, observe, then explain. A slider without an interpretable consequence adds little.
- Prefer a short definition, a legible equation, and named parameters over repeated explanatory paragraphs. Keep the inference limit next to the conclusion it qualifies.
- Write understanding checks that distinguish likely misconceptions, with feedback explaining why an answer works.

## Evidence and review
Use the supplied dataset and verify external technical claims against primary sources. Distinguish an observed sample relationship from future forecasting performance. Do not invent evidence of learning effectiveness.

Deliver a coherent lesson or scoped revision, plus the checks performed and any unresolved teaching decision. If the instructor requests discussion first, offer concrete alternatives without editing.

## A2 example
The sequence is prices → simple/log returns → distribution versus time order → ACF and Ljung–Box → memory. The shuffle experiment keeps the set of returns fixed while changing their order. An AR model is deliberately outside the introductory explanation of ACF. These are A2 choices, not a universal lesson template.

02

Reproducible figures

One statistical meaning across two implementations.

Data + units + estimator + defaults → browser figure + Python.
Read the skill instructions
---
name: course-reproducible-figures
description: Create or revise course statistics figures with downloadable Python examples when the web display and reproduction must agree on data, units, estimators, and parameters.
---
# Build reproducible course figures

Inspect the existing browser calculation and source data before writing a second implementation. Record the figure contract: data columns and window, missing-value handling, units, transformation, estimator, parameter defaults, and any random seed.

## Keep the two implementations consistent
- Match the statistical definition, not only the appearance. A correlation of overlapping pairs and an ACF using a whole-sample denominator can differ.
- Keep percentages and percentage points explicit. State whether standard deviation uses a sample or population denominator.
- For a KDE, distinguish an absolute bandwidth from a library's dimensionless bandwidth factor.
- For simulated data, specify the generator and seed. Equal seeds across different generators do not guarantee equal samples.
- Make chart controls and labels read the same state as the calculation. Give changing settings an observable meaning.
- Use equal units and axis scales where geometric comparison requires them, especially yesterday-versus-today scatter plots.

Provide a standalone Python script with editable parameters and clear dependency and data instructions. Use paths relative to the script or an explicit input path; never depend on the author's private folders. A static reproduction may match a selected interactive state; state which one.

## Verify observable agreement
Run the script against the packaged data. Compare representative numbers and endpoints with the web implementation using a tolerance appropriate to floating-point and displayed rounding. Check the downloadable code, inline code, and bundle are consistent. Open the chart to inspect ticks, units, and clipping.

## A2 example
A2 uses 93 BTC daily prices and 92 log returns. Its BTC ACF uses a whole-sample denominator; the simulated memory charts use overlapping-pair Pearson correlations. Preserve and explain this distinction when reproducing them rather than silently substituting one estimator for the other.

03

Visual review

Inspect the page a learner actually sees.

Render → inspect formulas, axes and states → fix → inspect again.
Read the skill instructions
---
name: course-visual-review
description: Inspect and improve course webpage readability when formulas, charts, callout boxes, responsive layouts, or interaction states have visual defects.
---
# Review a course page visually

Read the local styling and inspect the rendered page before editing. Preserve the requested visual language and content scope. Treat a screenshot as evidence of a visible defect, not as a complete account of the underlying layout.

## Formulas
- Keep a variable close to its relation sign with balanced spacing on both sides.
- Use one shared relation column for multi-line derivations. Align equals and approximate-equals signs. Center a relation sign on a fraction's rule.
- Keep subscripts attached, limits legible, and terms together where possible. Do not use repeated spaces to align mathematical content.
- Use a single line for a short calculation if it fits; allow structured wrapping at narrow widths.

## Charts and layout
- Check ticks, units, label clipping, plot proportions, caption lengths, and the balance between adjacent figures.
- Give color a stable meaning. Use a small set of existing box types; do not invent a new fill for every example.
- Check default, final, replay, selected, expanded, and error states where relevant to the change.
- Check at a desktop width and a narrow mobile width. Keep native keyboard focus, readable labels, and a reduced-motion alternative.

## Verify the fix
Inspect the actual computed layout and a fresh screenshot after the change. Account for CSS cascade and stale asset caches. A selector existing in a stylesheet does not prove that it wins. Report the states and widths actually inspected; do not claim a comprehensive accessibility audit from a small visual check.

## A2 example
A2 revisions aligned = and ≈, reduced excessive left-hand formula spacing, fixed clipped price-axis labels, and equalized scatter-plot axes. Convert these into reusable checks rather than hard-coded A2 pixel dimensions.

04 / CONTRIBUTION PROTOCOLFULL GUIDE ↗

Improve one thing.
Show why it helps.

Contribute a clearer explanation, a corrected calculation, a more legible chart, or a reproducible new lesson. Start with the learning problem.

  1. 01

    Describe the learner's difficulty.

    Name the page and section. Include a source for a technical correction or a screenshot for a visual defect.

  2. 02

    Make a focused change.

    Work on a branch or fork from current main. Keep the web figure and its reproduction consistent.

  3. 03

    Attach evidence.

    Explain the resulting behavior, the checks you ran, and any remaining limit. State how AI assisted and what you verified.

  4. 04

    Review, merge, then inspect live.

    A maintainer reviews teaching accuracy and the diff. Accepted changes enter the shared course through main.
